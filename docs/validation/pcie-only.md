# CPU-less variant (decision 0008, variant 3)

Build: `build_soc.tcl <out> nocpu 750 build/boot_rom_sd.hex -nocpu` (add `-pcie` for the host path, see stage B). No CPU netlist, OpenSBI or Linux: `fpga/rtl/nocpu_core.v` takes the place of the SoC netlist with the same bus ports. Everything else (DDR4, peripheral crossbar and peripherals, HDMI, LiteEth, `eth_dma`) is the normal `soc_top`.

## Stage A: UART2 test rig (board-tested 2026-11-17)
- `fpga/rtl/uart_rig.v` (+ `uart_rx.v`, existing `uart_tx.v`): line protocol on UART2 (CP2105 ECI, `/dev/ttyUSB1`, 230400 8N1, pins H17 RX / G19 TX, bank 67, VADJ 1.8 V jumper): `W addr data`, `R addr`, `B addr count`, `I`, `V`; replies `OK`, 8 hex digits, `ERR`, `HGRIG1`. The header of `uart_rig.v` is the specification. Addresses 0x40000000-0x7FFFFFFF go to DDR4 (AXI4, 256-bit, single beats), everything else to the AXI4-Lite peripheral crossbar. Host tools: `tools/rig.py` (CLI and library), `tools/rig_smoke.py` (board checks).
- Memory path: the rig and the hub DMA port (eth_dma, HDMI; 64-bit) share the DDR4 controller port through `nc_dw` (64 to 256 bit) and `nc_xbar` (2 masters, 256-bit). Without a CPU the interrupt vector is only readable with `I`.
- Simulation: `tests/rtl/tb_uart_rig.v` (101 checks: both ports, all eight lanes, strobes, errors, bursts across the memory/peripheral boundary, malformed lines, framing error, bytes during a reply, host baud error of 3 percent; two slave latencies; Icarus and Verilator), 15 mutants caught (`tests/rtl/run.sh`, `mut_rg_*`, `mut_rx_*`). Not simulated: the IPs `nc_dw`/`nc_xbar` (only the board).
- Build: WNS +0.266 / WHS +0.012, 16.1k LUT (`build/soc/nc2`, no timing fix needed).
- Board: `tools/rig_smoke.py --reset build/soc/nc2/soc.bit` passed 13 of 13: identification, DDR4 status, clock register, scratch, LED, die temperature, interrupt vector, decode error then bus alive, 64 random DDR words one by one and as a burst, three far addresses, `eth_dma` copying board-register bytes to an unaligned DDR4 address (hub DMA write path through the upsizer) and the HDMI scan-out running 0.2 s without late lines or read errors (hub DMA read path).
- Limits: a transaction a slave never answers stalls the rig until reset (no timeout); bytes sent before a reply completes are dropped; rig accesses are 32-bit single beats, so DDR4 throughput through it is serial-bound, not a bandwidth test.

## Stage B: PCIe host path (`-nocpu -pcie`)
- `pcie_ep` under `NOCPU` exports the host's BAR0 (64 KiB AXI4-Lite) as a master port; `soc_top` makes it a third master of the peripheral crossbar at 0xF8000000 + BAR0 offset (so BAR0 covers the same 64 KiB the CPU sees: UART lite, board registers, HDMI, `eth_dma`, and the endpoint's own register block at BAR0 + 0xA000 with the DMA window registers). The XDMA master (BAR1 DMA) already reaches DDR4 through the hub DMA port. The DMA window is closed at reset as in the endpoint build; the host opens it through BAR0 + 0xA070/0xA074.
- Simulation: `tests/pcie/run_sim.sh pcie_ep_nocpu` (vendor root-port bench, xsim, wrapper with a word memory on the new port).
- No live host exists on the bench (owner: edge connector and FMC not planned to be tested), so link, enumeration and host access remain simulation-only, as for the endpoint build.
- Build (2026-11-17, `build/soc/ncp1`, `-nocpu -pcie`): WNS +0.354 / WHS +0.003, 32.8k LUT, 43.0k FF, 71.5 BRAM, no timing fix needed. Not loaded on the board (the endpoint without a slot adds nothing the PCIe-less rig test does not cover).

## Lean card (`-card`, 2026-11-19)
`build_soc.tcl <out> nocpu 750 <any rom path> -card`: a separate top (`fpga/rtl/card_top.v`) with the DDR4 controller, the PCIe endpoint, the UART2 rig (`nocpu_core`) and two small register blocks; no SD, Ethernet, HDMI, I2C, SPI, GPIO, UART1, fan or boot ROM. The full-peripheral build stays as `-nocpu -pcie` (the option to keep them in). BAR0 map (rig address = 0xF8000000 + offset): 0x1000 `card_regs` (identity, build, status, scratch, LED), 0x2000 `user_regs` (hook window: 16 CTL words, 16 STS words, KICK pulses, event/enable, layout word; its `ctl`/`kick`/`irq` outputs and `sts`/`event_in` inputs are the attachment point for a future function, unconnected today), 0xA000 `pcie_regs`, and 0x4000 `user_ip` (16 KiB AXI4-Lite window for a future function block, a placeholder that reads 0 and ignores writes: `fpga/rtl/user_ip.v`); the rest is reserved and answers DECERR from the register crossbar (`xbar_card`, 2 masters: rig and host BAR0, 4 slaves). DMA reaches DDR4 through the closed-at-reset window. Details of identity and flash boot: `docs/validation/pcie-flash-enumeration.md`.

### Adapting the card build to a new function block (for example OpenMLA)
`fpga/rtl/user_ip.v` is the reference function block: replace its body and keep its connections. Three kinds exist, each with a self-test so the connection can be checked on the board before the IP does:
1. **Registers**: a 16 KiB AXI4-Lite window at BAR0 + 0x4000 (rig 0xF8004000), register clock `per_clk` (100 MHz). Window map: 0x000 ID "UIP1", 0x004 CAPS {layout, UIRQ, UMEM}, 0x008 IRQ_SET, 0x00C IRQ_PEND, 0x010 IRQ_SEEN, 0x014 START, 0x100 + 0x40 * i the self-test of DDR4 port i (`mem_probe.v`). `user_regs` (BAR0 + 0x2000: 16 control words, 16 status words, kick pulses, event/enable, `irq`) stays for the few bits a block needs next to its own map.
2. **Interrupts to the host**: `UIRQ` level lines (`-uirq N`, 1..6, default 6) on XDMA user interrupts 2..7 (vector 1 is `user_regs`, vector 0 the CPU doorbell; the IP now has 8 vectors). One MSI/INTx message per assertion (`irq_req.v`); a handler clears the cause and re-reads until none is pending. `IRQ_PEND` shows requests waiting for the host and needs a link (the XDMA core holds its interrupt logic in reset without one, so none is raised on the bench); `IRQ_SEEN` shows each line inside the PCIe clock domain with or without a link.
3. **DDR4 master ports**: `UMEM` independent AXI4 ports (`-umem N`, default 2), 256-bit data, 32-bit address, 4-bit ids, on `ui_clk` (333 MHz), through one crossbar (`xbar_mem`, slave 0 = rig and PCIe DMA, slaves 1..N = user ports) in front of the single DDR4 controller. The ports share the controller's bandwidth (10.7 GB/s peak at tCK 750 ps); none has a reserved share. A block that needs more than one port instantiates several; one block may also use a port per engine.
Constraints: BAR0 is 64 KiB shared by all windows (0x3000, 0x5000..0x9FFF and 0xB000..0xFFFF are free), larger maps need a bigger BAR0 in `xdma_ip.tcl`; AXI bursts must not cross 4 KiB; logic on a user port runs at 333 MHz (a slower block needs its own clock-domain crossing); crossings to `per_clk` need constraints in `card_board.xdc` (see the `u_probe` lines for the pattern).

#### How many DDR4 ports fit (2026-11-19/20, Vivado 2026.1, `-strategy Performance_ExtraTimingOpt`, default clocks)
The limits are the crossbar (AXI4 crossbar IP: 16 slaves, so 15 user ports at most, ids of 4 + log2(1 + N) bits stay within the controller's 8) and timing at 333 MHz. Area grows with N by about 1,000 LUT and 1,300 FF per port in total (from 28.8k LUT / 38.5k FF without ports to 42.4k / 56.2k with 14: a `mem_probe` plus the port's share of the crossbar); a real IP replaces the probe.
| User ports | WNS / WHS (ns) | LUT | FF | Note |
|---|---|---|---|---|
| 0 (placeholder only, `card2`) | +0.284 / +0.010 | 28.8k | 38.5k | direct nocpu_core to DDR4 |
| 4 | +0.043 / +0.006 | 33.5k | 42.1k | first `mem_probe` (adders before the compare) |
| 14 | -0.384 / +0.001 | 43.6k | 48.4k | same probe: the failing path was the probe's pattern/compare chain, not the crossbar |
| 14 | **+0.107 / +0.011** | 42.4k | 56.2k | pipelined `mem_probe` (registered pattern, compare one stage later) |
So 14 user ports close timing here (15 is allowed by the script and untried). One crossbar stage costs the rig and PCIe DMA path one more hop. Measured on the board with the first probe and 4 ports (`card_u4`, one run at a time, 1024 beats of 32 bytes, burst of 16, one burst in flight): about 7.0 to 7.6 GB/s write and 4.2 GB/s read per port, latency bound; no concurrent figure was taken (the first concurrency test started the ports one after another and did not overlap; `START` now starts them in the same clock). `tools/card_smoke.py` runs each port alone, then all together, and checks the data again through the rig.
