# 0006 — Coherent SoC with a 128 KiB L2 as the default

- Status: accepted (owner, 2026-11-08)
- Date: 2026-11-08

## Context
The non-coherent SoC (`soc_base`) has no L2: every L1 miss goes to the DDR4 controller (about 165 ns random, 31 cycles per sequential line). The L2 was shelved in
October pending a Linux workload (docs/validation/l2-study.md). The coherency hub is needed for any future DMA master anyway.

## Alternatives
- No L2, no hub (`soc_base`): smallest and fastest sequential read; no DMA coherence.
- Hub only (`soc_dma`): ~29 % slower sequential read (membench), no random-access gain.
- Hub + 256 KiB L2: same Linux gain as 128 KiB, 8 URAM, missed 333 MHz timing by 0.154 ns.
- Hub + 512 KiB or larger: no measured benefit worth the Fmax loss.

## Decision
Default SoC netlist: VexiiRiscv RV64IMA + coherency hub + 128 KiB 4-way L2 with the data banks in UltraRAM, generated by `fpga/scripts/cpu/gen_default_soc.sh`
as `soc_l2u_128k_w4`, built with `build_soc.tcl` (CPU and DDR4 on ui_clk 333.33 MHz). The DDR4 interface, peripherals, address map and boot flow are unchanged.

## Consequences
- +2.2k LUT, +3.2k FF, +2 BRAM tiles, 4 of 64 URAM versus the non-coherent SoC; the coherency hub's DMA port is available for later use.
- Fmax: the 128 KiB L2 meets 333 MHz (WNS +0.020, WHS +0.010 on the full SoC); larger L2 sizes cost about 15 MHz per doubling.
- `soc_base` remains buildable for comparison and the simulation tests still default to it.
- The L2 benefit is limited to random access over sets between the L1 (16 KiB) and 128 KiB; sequential and compute-bound code is unchanged.

## Validation
Board, full SoC under Linux (docs/validation/l2-study.md): gzip 13.5 -> 8.7 s, shell loop 2.8 -> 2.2 s, gunzip/md5sum/tar unchanged, sort 5 % faster.
Not measured: Ethernet throughput on the L2 image, hub-only Linux image, DMA with the hub.

## Revisit triggers
A workload that regresses on the hub (sequential-read bound), a DMA master that needs the hub differently, or timing pressure from new logic (the L2 has 0.02 ns of slack).
